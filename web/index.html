WebMCP Readiness Checker

Enter a page that registers WebMCP tools. It will be opened in a browser, every tool will be called, and each response will be checked against what the tool claimed it returns.

The page must be publicly reachable. Tools are called with arguments synthesised from their own declared schema — see the caveat below.

What this checks

  • Output contract — does the tool declare what it returns? Today outputSchema does not exist in the spec, so this is reported, never enforced.
  • Schema documentation — does every input field carry a description, so an agent knows the expected format?
  • Required fields — does a call that omits a field declared required actually get rejected?
  • Schema-implementation agreement — does a tool reject input that satisfies its own declared schema?
  • Determinism — do two identical calls return the same shape?
  • Tool budget — how many tools does the page register at once?

Caveats

  • Your tools will be called. Arguments are synthesised from each tool's declared schema. Give any destructive field a safe default before pointing this at production.
  • Determinism is compared by shape, with values discarded, so a timestamp is not mistaken for a broken contract.
  • Read-only. No authentication, no accounts, nothing stored. One browser per scan.

Findings come from rules derived from the WebMCP spec's own guidance. Source and the full registry report are public.
